# Alunixa X v1.0.35 — 逐模型协议与选定上游修复

## 完成内容

### 普通自定义配置供应商的逐模型协议

- 在普通 API 供应商的模型表格中为每个模型增加协议选择。
- 支持 `Responses`、`Chat Completions`、`Completions`、`Anthropic Messages` 和 `Gemini Generate Content`。
- 模型协议留空时继承供应商级默认协议，因此旧配置不需要迁移即可继续工作。
- 模型列表、上下文窗口、图片处理和协议映射使用同一组可排序行，模型重命名、导入和追加模型不会错配。
- 保存、导入、供应商切换和启动前配置生成均保留 `modelProtocols`；首次启用跨协议模型时，Codex 会通过本地 Responses 代理访问真实上游。
- 无效 JSON、未知协议、空模型名和不完整配置会在保存前报错，不静默降级到错误端点。

### CodexPlusPlus v1.5.0 的部分非广告修复

- **模型名污染防护**：配置回读和保存前拒绝包含换行、控制字符、反斜杠或供应商配置关键字的污染模型名，避免 TOML 转义在每次保存时继续膨胀。
- **原生 Responses 压缩透传**：原生压缩端点的请求体、opaque 状态、模型和响应不再被改写成普通摘要转换；跨协议供应商仍明确拒绝无法表示的原生压缩请求。
- **GPT-6 Fast 识别**：Fast 服务档位界面加入 `gpt-6-astra`、`gpt-6-sol` 和 `gpt-6-luna`。
- 只同步与本项目兼容的修复；上游广告、赞助商、推广入口、推广脚本和推广资源均未同步。

## 使用与回退

安装后打开 Alunixa X，在供应商的模型表格中为需要的模型选择协议并保存；首次启用协议代理时按提示重新启动 Codex。旧配置中的 `modelProtocols` 为空时仍按供应商协议直连或使用原有代理路径。

若某个上游不接受请求中的高级字段，请把该模型切回其实际支持的协议，或删除该模型的单独协议选择让它继承供应商默认值。不会删除会话、供应商、密钥或缓存；如需回退，安装上一版并恢复对应供应商的原协议即可。
