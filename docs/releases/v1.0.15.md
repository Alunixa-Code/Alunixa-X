# Alunixa X v1.0.15 · 启动前全面配置审计

本版完成上一轮清理后的后续要求：Alunixa X 每次启动 Codex 或重新激活已有 Codex 实例前，全面检查所有会影响启动的配置来源，避免开关已经关闭但实际配置仍残留或高级提示词引用失配喵~

## 启动前审计范围

- 检查 `config.toml` 的有效 TOML、退役实验性上下文字段、`agents.max_threads`、image_gen MCP、禁用 WSS 的 provider 设置和当前供应商配置状态喵~
- 检查 `auth.json` 的有效 JSON 对象、`hooks.json` 的有效结构和 Alunixa X 托管 Hook 数量，错误配置会在启动前明确失败喵~
- 检查 Alunixa X 保存的公共配置、上下文配置和每个供应商配置片段，禁止旧退役字段通过快照、供应商切换或导入重新写回喵~
- 检查高级提示词配置引用、托管正文、`.last-good` 备份、普通文件属性、UTF-8、文件大小和 NUL 字符；外部用户文件只读检查，不会被自动覆盖喵~

## 关闭开关后的清理

- Computer Use 关闭时只移除 Alunixa X 自己写入的插件、托管市场、`js_repl` 和通知项，保留用户自建插件及市场配置喵~
- 托管插件市场关闭时移除 Alunixa X 自己的市场和对应插件条目，保留用户选择的第三方市场和插件喵~
- 启动审计会在配置写入完成后再次执行窄范围修复与校验，无法安全判断归属或发现不一致时停止启动，不用空默认配置覆盖现有内容喵~

## 启动路径

- 正常首次启动和已有 Codex 实例重新激活都会经过同一启动审计门禁喵~
- 审计日志只记录检查文件数、配置区段数、提示词文件数和修复数量，不记录配置正文、凭据或提示词内容喵~
- 本版不重启用户当前已经运行的 Codex，也不替用户修改未由 Alunixa X 管理的外部配置；安装后下一次通过 Alunixa X 启动或重新激活时生效喵~

## 验证与发行

- 本地 core lib、relay switch、installer、manager Windows 契约、Rust formatter 和 workspace all-targets locked check 均通过喵~
- 正式 GitHub Actions 必须通过 Windows x64、macOS x64、macOS arm64 的完整测试、构建、安装包结构校验和六项资产 SHA-256 校验后才发布喵~
