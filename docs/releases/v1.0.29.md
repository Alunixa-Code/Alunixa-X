# Alunixa X v1.0.29 — Codex 白屏后台恢复与启动不闪退

## 中文

本版修复 v1.0.28 在 Codex 原生界面等待超时后主动结束整个桌面进程的问题，并对用户确认的 app-server 白屏恢复路径增加一次自动重试喵~

### 已确认的问题与修复

- v1.0.28 的 renderer 注入、模型目录和 dispatcher 已经成功，但 20 秒内未找到原生 composer 时，启动流程仍把该状态作为致命错误，并结束打包激活返回的 `ChatGPT.exe` 主 PID；这就是通过 AX 启动后窗口闪退的已证实原因喵~
- 用户确认直接启动 Codex 也可能白屏；结束子 `codex.exe` 后出现原生错误页，点击 `Try again` 能恢复。首次 app-server 卡住的上游原因仍未知，本版不把它错误归因于代理、配置或 AX 注入喵~
- AX 现在使用当前 Codex 原生错误页相同的 `codex-app-server-restart` dispatcher 合约：注入验证通过后等待 10 秒，仍未就绪则自动重启一次本地 app-server，再等待 25 秒喵~
- 若自动恢复仍无法确认原生界面，启动器写入 `running_degraded`，保留 Codex、Helper 和注入桥；不会关闭整个窗口，管理器中英俄界面会提示在原生错误页点击 `Try again` 喵~
- 真正的模型、配置或注入契约错误仍明确失败并执行原有回滚，不会用“降级运行”掩盖可能导致错误路由的问题喵~

### 状态判断与数据保护

- 主页、设置、登录、导航、侧栏及对话 composer 都可证明原生界面可用；加载 spinner、`aria-busy`、AX 自身覆盖层、隐藏 DOM 和带重试按钮的错误页不会被标为成功喵~
- 不使用 `taskkill`，不终止 `ChatGPT.exe`，不修改系统代理、hosts 或证书，不删除会话、供应商、密钥、`auth.json` 或 `config.toml` 喵~
- 直接从官方 Codex 快捷方式启动不经过 AX 注入，因此仍由官方应用自行处理首次后台卡住；自动恢复针对通过 Alunixa X 启动的路径喵~

### 验证与边界

- 当前源码完整 Rust workspace：42 套件 `1183 passed / 0 failed / 1 ignored`；唯一忽略仍是既有 app-server 子进程测试入口。前端 `136/136`，全目标编译、TypeScript、Vite、中英俄字典、品牌、格式和差异检查通过喵~
- 生产 Chromium 夹具验证了 spinner、普通原生壳层、AX overlay、隐藏 DOM、composer 和 `Try again` 错误页；只读实际 `app.asar` 验证了原生重启消息喵~
- 为避免中断用户当前已经恢复的任务，没有重启真实 Codex，也没有在活动会话中热触发重启消息。正式标签由 GitHub Actions 在 Windows x64、macOS x64 和 arm64 重新执行测试与构建；安装后仍需完成真实启动现场复测喵~

## Русский

Версия исправляет завершение всего окна Codex после тайм-аута проверки нативного интерфейса и добавляет один автоматический перезапуск локального app-server по тому же контракту, который использует кнопка `Try again`.

- В v1.0.28 мост и модели уже загружались, но отсутствие composer в течение 20 секунд считалось фатальной ошибкой, после чего AX завершал главный `ChatGPT.exe`.
- Теперь после успешной проверки инъекции AX ждёт 10 секунд, отправляет один `codex-app-server-restart` для `local`, затем ждёт ещё 25 секунд.
- Если интерфейс всё ещё не подтверждён, состояние становится `running_degraded`, а Codex, Helper и мост остаются запущенными. Реальные ошибки конфигурации или инъекции по-прежнему завершаются явной ошибкой и откатом.
- `ChatGPT.exe` не завершается, сессии, провайдеры, ключи, `auth.json` и `config.toml` не сбрасываются; системный прокси не изменяется.
- Локальные проверки: Rust `1195/0/1`, frontend `136/136`, TypeScript, Vite, переводы, форматирование и production Chromium fixture. Рабочий сеанс пользователя не перезапускался, поэтому реальный запуск нового установленного бинарника остаётся отдельной проверкой.

## English

This release fixes the v1.0.28 path that terminated the entire Codex desktop after native-UI readiness timed out, and adds one bounded local app-server restart through the same dispatcher contract used by Codex's `Try again` recovery page.

- In v1.0.28, renderer/model injection could already be valid, but failure to find a composer within 20 seconds was still treated as fatal and AX terminated the packaged `ChatGPT.exe` PID.
- After injection verification, AX now waits 10 seconds, dispatches one local `codex-app-server-restart`, and waits another 25 seconds.
- If the native UI is still unconfirmed, the launch becomes `running_degraded` while Codex, Helper and the bridge stay alive. Actual configuration, model or injection-contract failures remain strict failures with the existing rollback behavior.
- No `taskkill`, `ChatGPT.exe` termination, session/provider/key deletion, `auth.json`/`config.toml` reset, or system-proxy change is used.
- Local gates passed with Rust `1195/0/1`, frontend `136/136`, all-target compilation, TypeScript, Vite, translations, formatting, branding and a production Chromium fixture. The active recovered user session was deliberately not restarted, so installed-binary desktop reproduction remains a separate field check.
