# Alunixa X v1.0.28 — 应用代理恢复与配置一致性修复

## 中文

本版交付应用隔离代理恢复、Agent 配置一致性和新版 Codex 界面适配的定向修复，不宣称上游全部变更或白屏的所有原因均已解决喵~

### 1. 新增应用隔离代理诊断与恢复

- 在 **Agent 能力 → 运行与配置核对** 对照普通进程与 Codex 应用包实际读取的注册表视图，显示包身份、视图指纹、启用状态和本机端点，不输出代理凭据喵~
- 启动自动修复只处理：手动代理已启用、没有 PAC、全部端点是本机地址、连续探测均明确拒绝连接的情况；正常代理、外部代理、PAC、未知状态和已关闭代理的残留地址均保留喵~
- 操作在同一应用包上下文内完成：修订核对、备份、仅关闭 `ProxyEnable`、回读验证；提供恢复入口，恢复前再次检查包身份和修订喵~
- 不硬编码 Silo、端口、包版本或后台缓存路径，不通过每次启动清空代理解决问题；旧版配套启动器不支持探测协议时明确报告，避免误启动 Codex 喵~
- 现有证据确认包视图中的失效代理导致了请求失败，但最初写入该地址的程序仍未知，本版不把写入者归因于 AX 喵~

### 2. 配置、工具与 Agent 开关

- 盘点 38 项设置，区分管理器期望、磁盘/CLI 默认、缺少依赖、不支持、未知和待重启状态喵~
- Fast 与 Goals 使用实际后台的特性表核对支持和默认值，关闭明确写入 `false`；增加 Goals 控件，避免把删除键当作关闭喵~
- 启动、登录和供应商切换不再无条件重放 AX 缓存中的 Fast、Goals、WSS 和线程数；供应商切换同时保留当前全局原生设置及其缺省状态喵~
- 修复工具页删除停用项后，启动注册又重新启用插件的问题：MCP 和插件保留显式 `enabled=false`，旧 MCP `disabled=true` 定向迁移；内联插件配置和自定义字段也保留喵~
- Hook 信任状态以当前文件为准，不让旧供应商快照覆盖新 hash、启用状态或复活已撤销条目；原始配置编辑仍可明确修改或撤销信任喵~
- 保存采用修订检查、跨进程锁、备份、原子替换和回读；失败恢复本次修改，但不覆盖外部程序刚更新的认证或配置喵~
- 外部修改后需重新读取，解析失败不使用默认值冒充结果；即时保存其他开关也会携带尚未保存的原生能力编辑喵~
- 不支持的 Zed settings 同步不再显示为生效；不删除会话、供应商或密钥，不全量重置 `auth.json` / `config.toml` 喵~

### 3. 启动与原生界面适配

- 适配新版 `app-shared-*` 分块中的设置服务、Host RPC、dispatcher 和终端契约，不再只依赖旧分块和固定短导出名喵~
- 快速启动不再伪造 Statsig 初始化成功；重复启动仅激活现有窗口，不重复接管其 helper 和配置喵~
- 注入及原生界面验证有独立截止时间；失败记录初始化阶段及首次捕获的脱敏异常位置，结束无限等待，而非隐藏转圈或无条件标为成功喵~
- 概览分别检查 helper 响应和原生界面，app-server、模型请求未验证时明确显示未验证；菜单出现、历史端口记录不是“5/5 链路在线”的依据喵~
- 定向同步上游路径发现、配置合并、模型目录切换、基础控件与 Windows `asInvoker` 等改动；保留 AX 品牌、俄语、现有媒体和协议保真修复，不导入广告喵~

### 使用与升级

1. 安装完整同版程序，ZIP 部署时保留 manager、launcher、imagegen MCP 三个程序的配套关系喵~
2. 打开 Agent 能力页检查配置；有外部变更先重新读取，有解析错误先修正对应文件，不删除整个配置目录喵~
3. 已启用自动代理修复时，下次 AX 启动前会做定向检查；也可点击“检查代理 → 备份并修复”，完成后按页面提示重新启动受影响的 Codex 进程喵~
4. Fast、Goals、WSS 等保存后，完整退出旧 Codex 再从 AX 启动；不会自动关闭正在使用的会话喵~
5. 配置事务备份位于所用 Codex home 下 `alunixa-x-config-transactions`，代理备份位于 AX 状态目录的 `packaged-proxy-backups`；按清单核对后定向恢复，不覆盖更新后的认证喵~

## Русский

### Что изменилось

Это целевое исправление прокси, согласованности настроек и совместимости интерфейса, а не заявление о завершении всей синхронизации с upstream или устранении всех причин белого экрана.

- **Прокси приложения:** сравниваются обычный и изолированный контексты реестра. Исправление выполняется в контексте выбранного пакета: проверка версии состояния, резервная копия, отключение только `ProxyEnable`, повторное чтение. Есть восстановление копии.
- **Автоматическое восстановление:** только включённый ручной прокси без PAC, все адреса локальные, все проверки явно отклонены. Рабочие и внешние прокси, PAC, неизвестные состояния и адрес отключённого прокси не меняются. Silo, порт и версия пакета не зашиты в код.
- **Agent:** проверяются 38 настроек. Намерение менеджера отделено от файла, значений CLI по умолчанию и состояния работающего процесса. Fast и новый переключатель Goals сохраняют явные `true`/`false`; неподдерживаемые возможности блокируются.
- **Сохранение:** блокировка между процессами, проверка ревизии, копия, атомарная запись и повторное чтение. Ошибка возвращает переключатель в прежнее состояние; внешнее обновление авторизации не перезаписывается.
- **Провайдеры:** запуск и переключение больше не воспроизводят устаревшие Fast, Goals, WSS и число потоков из кеша AX. Отсутствие глобального ключа также сохраняется.
- **MCP и плагины:** отключение остаётся `enabled=false`, поэтому регистрация при запуске не включает плагин снова. Сохраняются отключение в inline-таблицах и пользовательские поля.
- **Hooks:** актуальное доверие и его отзыв не заменяются старым снимком провайдера. Редактор исходной конфигурации по-прежнему позволяет явно отозвать доверие.
- **Запуск:** поддержано обнаружение служб в `app-shared-*`; больше нет искусственного статуса готовности Statsig. Повторный запуск активирует существующее окно. Неудачная инициализация ограничена по времени и показывает этап ошибки.
- **Проверка состояния:** наличие меню или порта не означает готовность интерфейса либо успешный запрос модели. Непроверенные app-server и запросы показываются отдельно.

### Обновление и восстановление

Установите все программы одной версии. В разделе возможностей Agent перечитайте настройки при обнаружении внешнего изменения. После сохранения Fast/Goals/WSS завершите старый Codex и запустите его через AX, когда это удобно; активная задача автоматически не закрывается.

Копии конфигурации находятся в `alunixa-x-config-transactions` внутри выбранного Codex home, копии прокси — в `packaged-proxy-backups` каталога AX. Восстанавливайте только нужные файлы после проверки текущего состояния; не заменяйте обновлённые данные входа. Сессии, провайдеры и ключи не удаляются.

### Границы проверки

На Windows проверены изолированные конфигурации установленного CLI, чтение контекста пакета, контракты реального ASAR и интерфейс менеджера. Финальный тег проходит тесты и сборку в GitHub Actions для Windows x64, macOS x64 и arm64.

Не выполнены повторное воспроизведение белого экрана на рабочем экземпляре, сравнение двух способов запуска, реальный запрос модели, изменение рабочего прокси и настольная проверка macOS. **Полная синхронизация upstream, включая миграцию старой модели Skills, ещё не завершена.** Тесты с временными данными не выдаются за эти проверки.

## English

### Changes

This is a scoped proxy, configuration-consistency and desktop-compatibility patch. It does not claim that every upstream change or every cause of a white screen has been resolved.

- Inspect both host and actual packaged-app registry views. Repair runs in the selected package context, checks revisions, backs up first, changes only `ProxyEnable`, and verifies readback. Restoration checks identity and revision again.
- Automatic repair is limited to enabled manual proxies without PAC, with exclusively loopback endpoints that repeatedly refuse connections. Working, external, PAC, disabled and unknown configurations are preserved. Package versions, Silo IDs and ports are not hard-coded.
- Audit 38 settings, distinguishing manager intent, disk/CLI defaults, dependencies, unsupported states and pending restarts. Fast and the new Goals control explicitly save both on and off.
- Use revision checks, cross-process locking, backups, atomic writes and readback. Failed saves roll back owned changes without overwriting external authentication refreshes. Immediate saves retain pending native-capability edits.
- Stop replaying stale Fast/Goals/WSS/thread-limit intent at launch, login and provider switch. Preserve absent global preferences as well as explicit values.
- Keep disabled MCP/plugin entries explicitly disabled so startup registration cannot re-enable them. Preserve inline plugin values and unrelated custom fields.
- Preserve current Hook trust, including revocations, rather than stale provider snapshots. Explicit raw-file edits can still revoke trust.
- Discover native services in newer `app-shared-*` bundles. Do not fabricate Statsig readiness. Bound initialization, record sanitized error locations and activate rather than reinitialize an existing instance.
- Separate actual helper and native-UI checks from app-server/model calls. A menu, historical port or process alone is not verified readiness.
- Port selected upstream compatibility and UI fixes without advertisements; retain AX branding, Russian, media support and protocol-fidelity changes.

### Upgrade, evidence and limits

Install matching manager, launcher and imagegen MCP programs. Reload settings after external changes. Restart Codex through AX when convenient to apply restart-bound changes; this patch does not automatically terminate active work or reset authentication.

Configuration transaction backups are under the selected Codex home's `alunixa-x-config-transactions`; proxy backups are in AX's `packaged-proxy-backups`. Restore selectively after checking current state, not by overwriting freshly updated credentials.

Read-only package inspection, isolated installed-CLI configuration checks, real ASAR contract checks and Chromium manager tests were performed on Windows. GitHub Actions tests and builds the final tag for Windows x64 and both macOS architectures.

Live white-screen reproduction, direct-versus-AX desktop startup comparison, real model requests, mutation/restoration of the working proxy, every adapter's end-to-end behavior and macOS desktop operation remain unverified. **Full upstream synchronization, including the legacy Skills storage migration, remains unfinished.** Sessions, providers and keys were not removed, and isolated tests are not presented as live acceptance.
