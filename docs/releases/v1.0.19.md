# Alunixa X v1.0.19 · 生图模型管理与 AX 搜索入口

本版新增独立的 MCP 生图模型管理，并让 Windows/macOS 的安装入口明确包含 `AX`，保留 v1.0.18 的协议保真和防重复调用修复喵~

## 新增：生图模型

- 左侧新增“生图模型”栏目，可添加、编辑、删除多组 API 地址、API Key、Model，并可选填写便于区分的名称喵~
- 拖动手柄上下排列，最上方自动成为默认模型并显示“默认”徽标；排序自动保存，也支持键盘拖拽和上下移动按钮喵~
- 新增项放在末尾，不抢占现有默认；删除默认项后下一项成为默认；保存失败时不提交新顺序，不将失败的新默认展示为成功喵~
- 编辑 Key 留空保留原 Key，列表只显示非敏感字段；离开或刷新正在编辑的页面前先确认，不静默丢弃表单喵~

## MCP 的实际生效方式

- 接口为兼容 OpenAI Images 的 API；生成使用 `/images/generations`，带输入图的编辑使用 `/images/edits`，两条路径都使用选中配置的 API/Key/Model，保留多图、mask 和已有生图参数喵~
- 默认调用不传 `model` 或 `profile_id` 时使用首项；也可显式选择其他已配置 model，或通过 profile_id 区分同名模型配置喵~
- 每次调用重新读取配置，已经加载的新版 MCP 不需要因更改模型或顺序而重启；首次使用仍需开启增强功能并通过 Alunixa X 启动 Codex 加载 MCP 喵~
- 独立生图配置无需开启对话供应商管理，不更改当前对话模型；删除全部生图配置后恢复原 Helper/对话供应商及原默认生图模型喵~
- 不在多个生图配置之间自动重试或轮换，不重放结果不明的生成请求；生成 POST 不跟随重定向，图片下载不携带生图 API Key，失败不回显上游原始错误体或签名 URL 喵~

## 配置与完整性

- 配置存入本机既有设置文件的有序 `imageModels` 数组，复用原子写入、锁及完整配置备份喵~
- 通过独立命令脱敏读取和定向保存，Key 按稳定 ID 保留，不随排序错配；普通设置保存不覆盖最新生图配置喵~
- 生图编辑只替换原始 JSON 的 `imageModels` 一节，保留其他设置和未知扩展字段，不因为加载旧版结构后重新序列化而丢失数据喵~
- 两个窗口同时修改时使用修订校验，旧窗口明确要求刷新，不静默覆盖新配置；普通设置、供应商切换、回填、上下文设置的 UI 回包及诊断报告均不返回生图 Key 喵~
- 完整配置备份仍保留恢复所需的 API/Key/Model 与顺序，不因 UI 脱敏丢失存储内容喵~

## Windows / macOS 搜索 AX

- Windows 安装器和“安装维护”增加开始菜单入口 **AX - Alunixa X**、**AX Launch - Alunixa X**，保留原品牌入口，并在卸载时清理对应别名喵~
- macOS 应用实际文件名及 `CFBundleName` / `CFBundleDisplayName` 改为 **Alunixa X (AX).app**、**Alunixa X Launch (AX).app**；安装到“应用程序”后可通过 `AX` 搜索喵~
- 保持原 bundle ID，识别新旧名称与混合安装；有同级已解析应用时优先按具体路径启动，不因旧 bundle ID 缓存误启旧版本，也不自动删除旧安装喵~
- 修复 macOS “安装维护”路径未携带生图 MCP 程序的问题，安装前校验 companion，复制后保持可执行权限；正式 DMG 打包和全部 CI 路径同步新名称喵~

## 验证与升级

- 新增配置增删改/并发冲突/备份恢复、MCP 本机 HTTP 生成及编辑/默认热读取/Key 隔离、安装入口/旧名兼容、回包脱敏及下载错误回归喵~
- 生产前端使用隔离内存 Tauri fixture 验证鼠标拖拽、键盘排序、默认持久化、Key 留空保留、失败回滚、导航保护及深浅主题窗口布局喵~
- 正式 Windows x64、macOS Intel、macOS Apple Silicon 由同一标签的 GitHub Actions 执行完整前端/Rust 回归并构建六项安装资产，不复用旧版二进制喵~
- 本轮没有替用户安装、重启 Codex/Helper/CDP 或修改真实配置；新入口需安装新版，系统搜索依赖系统对已安装应用的正常索引，未将隔离测试描述为每台用户机器上的系统搜索实测喵~
- 原 v1.0.18 标签和发行资产保持不变；本页末尾由正式工作流附加产品提交、Actions 来源与六项安装文件 SHA-256 喵~
