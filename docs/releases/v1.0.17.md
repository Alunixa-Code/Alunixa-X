# Alunixa X v1.0.17 · 供应商上下文保存与配置预览一致性

本版针对供应商设置上下文窗口后保存、config.toml 仍显示旧值的问题，区分“非启动模型更新模型目录”的正常行为与确实存在的预览、清理、单位解析问题喵~

## 修复与改进

- 自定义多模型供应商的配置预览使用所选启动模型的实际参数，不再使用旧的供应商汇总窗口和压缩值；通用配置合并完成后再应用明确模型设定，与后端写入顺序一致喵~
- 启动模型提供显式选择入口；保存当前供应商时，根级 `model_context_window` 和 `model_auto_compact_token_limit` 跟随启动模型，其他模型的配置保存在模型目录，不会因为编辑它而擅自切换启动模型喵~
- 清空自定义模型窗口后移除前一个模型遗留的根级覆盖；关闭自动压缩后清除汇总阈值和托管 root 项，避免开关与实际配置矛盾喵~
- K/M 与小数单位使用一致解析，`1M` 写为 `1000000`、`1.05M` 写为 `1050000`；无效或溢出的数值被拒绝，不写成负数或残留旧窗口喵~
- 带注释的 TOML 表头也能正确区分根配置与嵌套 profile，预览和表单只更新对应 root 键，不误改嵌套 profile 参数喵~
- 供应商保存后以及下次启动前增加窗口/阈值回读一致性检查；发现失配明确失败，供应商保存沿用既有回滚流程喵~

## 保留的配置保护

- 明确编辑当前启动模型并保存，会更新对应磁盘窗口参数，不再把成功提示作为唯一证据；隔离测试同时验证外部高级提示词文件和引用不被覆盖喵~
- 编辑非启动模型时只更新该模型目录，不更改当前启动模型、正在运行的任务、外部提示词正文或用户凭据喵~
- 本版不改动第三方 `model_catalog_json` 指向的用户文件，也不声称运行中的旧任务会立即重新加载上下文喵~

## 验证与使用

- 修复前已复现五项前端问题及两个 Rust 问题；修复后的保存链路专项为 13/13，前端为 98/98，另有数值边界及启动回读回归喵~
- 正式发行由 Windows x64、macOS x64、macOS arm64 GitHub Actions 执行完整测试、构建与六资产校验后发布；发行页自动附加提交来源和 SHA-256 喵~
- 安装新版本后进入供应商详情，在“启动模型”选择希望应用到根配置的模型，再编辑其上下文窗口并保存；若只修改其他模型，根配置不变但模型目录会更新喵~
- 本轮没有改写用户真实 config.toml/auth.json，没有重启当前 Codex/Helper/CDP；运行中任务的参数仍需按 Codex 的加载时机生效喵~
