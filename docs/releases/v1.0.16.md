# Alunixa X v1.0.16 · Fast 模式、启动审计与排队消息修复

本版在 v1.0.15 启动前全面配置审计的基础上，新增 Agent 能力中的独立 Fast 模式开关，并把供应商写入、官方登录迁移和高级提示词内容校验纳入同一套配置一致性门禁喵~

## 运行中追加消息报错修复

- 修复当前 Codex 原生队列的编辑契约冲突：编辑先删除旧队列项，再提交却携带旧 messageId 要求更新，从而出现 `Error creating chat / App-server queued follow-up no longer exists` 喵~
- 仅在当前队列对象已确认成功删除该任务的旧 ID 时，按新增语义重新排队，保留编辑消息对象、附件上下文、提交参数及前后相邻位置，不中断正在运行的任务喵~
- 不吞掉报错、不伪造发送成功，不因网络超时、已被执行的队列项或未知旧 ID 自动重放消息；撤销恢复、过期、关闭增强或销毁队列后不再使用旧删除记录喵~
- 按原生方法结构识别受影响实现，不绑定压缩变量名或固定资源哈希；兼容新建/重建的队列，保持普通新增、仍存在的队列更新和原生 send-now 行为喵~
- 已使用本机 Codex `26.903.9818.0` 安装包的原生队列函数进行隔离复现：修复前同一错误，修复后只新增一次且顺序和输入保持一致；没有对当前运行窗口进行热注入喵~

## Fast 模式

- 管理器的 Agent 能力页面新增独立“Fast 模式”开关，不复用原有仅控制界面服务档位的 Fast 按钮喵~
- 开启开关后，Alunixa X 会在当前 Codex `config.toml` 中维护 `features.fast_mode = true`，标准写法为 `[features]` 下的 `fast_mode = true` 喵~
- 关闭开关后只删除 Alunixa X 管理的 `fast_mode`，不会删除同一 `features` 表中的其他 Codex feature，也不会覆盖用户的其他配置喵~
- 支持普通 `[features]` 表和 `features = { ... }` inline TOML 表；如果 `features` 被写成不兼容的标量，启动前会报告明确错误而不是覆盖用户配置喵~

## 配置一致性与启动门禁

- 设置保存、完整配置导入、恢复默认、供应商切换、官方登录迁移、纯 API、聚合和普通中转直接写入都会在成功写入后重新同步 Agent 能力设定喵~
- 每次通过 Alunixa X 启动 Codex，或重新激活已有 Codex 实例前，都会在真正启动前检查并窄范围修复由 Alunixa X 管理的配置喵~
- 检查范围包含 `config.toml` 的 TOML 结构、Agent 能力设定、`agents.max_threads`、供应商/provider、image_gen MCP、WSS、`auth.json`、`hooks.json`、保存的供应商配置片段、退役项和配置引用一致性喵~
- 发现关闭功能但配置残留、开启功能但配置缺失、表结构错误、文件不可读或不能安全修复时，启动会在 Codex 进程创建前失败，并记录不含正文、凭据或提示词内容的计数日志喵~

## 高级提示词

- 启动前会检查 `model_instructions_file` 引用必须是字符串，引用文件必须存在且是普通文件，并验证 UTF-8、空内容、大小限制和 NUL 字符喵~
- 启用托管高级提示词时，优先保留现有正文，其次恢复 `.last-good`，最后使用默认模板创建非空文件喵~
- 外部用户提示词文件仍然只读检查，不因 Alunixa X 设置值不同而覆盖；关闭托管提示词后遗留的空托管缓存不会阻塞启动喵~
