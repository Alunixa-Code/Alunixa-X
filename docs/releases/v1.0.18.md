# Alunixa X v1.0.18 · 协议保真、流式生命周期与防重复调用修复

本版修复本机 Helper 在 Responses、Chat Completions、Anthropic 和 Gemini 等协议之间转换时的类型混淆、历史丢失、流式结束异常与不确定请求重放问题喵~

## 修复与改进

### 思考、正文与执行结果分离

- 思考、普通正文和拒绝内容分别使用对应的输出类型及 SSE 事件，交错输出也保持独立 ID 和顺序，不把思考内容拼入最终正文喵~
- 流式 `<think>` 内容及时送往思考通道，不再缓存到整个思考块结束；未闭合的思考块不会作为正文泄漏，也不使用泛化正则删除正常用户文本喵~
- 上游返回 tool、debug、system 或 user 等非 assistant 角色时明确报协议错误，不把调试或执行输出冒充助手回复喵~
- 孤立或重复工具结果、缺失调用身份、非法函数参数不再被转换为用户消息或重新包装成另一种参数，避免模型因历史语义被改变而重复对话或调用工具喵~

### 原生历史与签名回放

- Anthropic 的 thinking、signature、redacted_thinking 及 Gemini 的 thoughtSignature、原始函数名和 ID 随历史保存为自包含原生回放项，不再依赖进程全局缓存喵~
- 续轮恢复前核对原始协议和对应输出历史；缺失、编辑或跨协议的回放项明确失败，不借用其他会话签名，不猜测丢失内容喵~
- 回放载体使用不作为正文显示的 `reasoning.encrypted_content`；`alunixa-x-replay-v1:` 是版本化 Base64 JSON 标记，不代表额外加密，也不写入诊断日志喵~
- 修复跨请求工具/响应 ID 冲突、缓存 token 重复扣减、图片 detail 和结构化输出参数丢失；能够等价表示的参数完整映射，不能表达的参数明确拒绝喵~

### 流式完整性与结束状态

- 严格处理 UTF-8 字节分片、BOM、CR/LF、无空行尾帧和 JSON，非法字节或损坏帧明确失败，不以乱码替换或静默跳过掩盖丢失喵~
- Chat 的 finish_reason 后继续接收尾部 usage 和终止帧，Anthropic 的 message_delta 后等待 message_stop，缺少完成依据的 EOF 不再伪装成功喵~
- 上游已声明停止生成却不发送终止帧时，使用独立的 5 秒收尾期限，心跳不会无限续期，避免这类请求一直停在思考中喵~
- completed、incomplete、failed 互斥，事件序号单调递增；达到 token 限制时返回 incomplete，不再把截断工具调用宣布为可执行完成喵~
- 保留原始工具参数分片，待函数名、ID、参数 JSON 和调用唯一性校验通过后才发送可执行 done，异常时保留已接收的半截参数但不触发执行喵~
- 上游忽略 stream 而返回完整 JSON 时生成符合相同下游契约的 SSE，保留文本、思考、工具和原生回放项喵~

### 防止结果不明时重复发送

- POST 已到达上游后的断连、响应头超时、500/503 等结果不明场景不自动重放或切换供应商，避免重复生成和重复工具调用喵~
- 保留连接尚未建立时的有限连接重试，以及明确 401/403/429 拒绝时的有界成员切换；已出现输出后禁止再次尝试 Responses ID 协商喵~
- 不支持的输入返回 HTTP 400 / `unsupported_protocol_conversion`，上游无效响应返回结构化 502，流式失败使用 `response.failed`，错误不注入对话正文喵~

## 能力边界

- 本版的原则是“不静默丢失、不混淆消息类型、不把失败伪装为完成”，不是让所有协议具备相同能力喵~
- 原生 Responses 和透明 HTTP/WebSocket 继续保留透传路径，不强制降级为 Chat Completions 喵~
- 服务端工具、未解析状态引用、无法等价表示的 phase/channel、旧 Completions 的工具/思考/非文本输入等明确要求支持对应能力的原生上游，不通过删除内容获得表面兼容喵~
- 尚不能可靠重建的流式 opaque `reasoning_details` 明确失败；完整支持矩阵和回滚方法见仓库 `docs/protocol-fidelity.md` 喵~
