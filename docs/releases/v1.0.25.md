# Alunixa X v1.0.25 — 多模型上下文窗口与 Codex 26.917 兼容修复

## 问题与根因

Codex 更新到 `26.917.9434.0` 后，用户在 Alunixa X 管理器中为不同模型保存的上下文窗口，可能与 Codex 对话内实际显示和使用的窗口不一致喵~

根因不是模型目录没有保存，而是旧版多模型配置同时把启动模型的 `model_context_window` 和 `model_auto_compact_token_limit` 写入根 `config.toml` 喵~

这两个根级键是 Codex 的**全局覆盖**，优先级高于 `model_catalog_json` 中逐模型的元数据喵~

例如启动模型 Terra 保存为 `272000`，随后切换到目录中配置为 `1050000` 的 Sol 时，Codex 仍会报告并使用 `272000`，于是管理器配置、模型目录和 Codex 实际行为出现分歧喵~

## 本次修复

### 多模型目录成为唯一窗口来源

- `RelayMode::CustomModels` 不再向根 `config.toml` 写入 `model_context_window` 或 `model_auto_compact_token_limit` 喵~
- 每个模型的上下文窗口、最大窗口和自动压缩 Token 阈值继续写入生成的 `model_catalog_json`，切换模型时由 Codex 读取对应模型项喵~
- 保存配置、切换启动模型、规范化旧配置和生成新目录时都会清理多模型模式遗留的根级窗口覆盖喵~
- 启动审计拒绝带有全局窗口残留的多模型配置，避免旧值在以后供应商写入或重启时再次回灌喵~

### 不改变其他配置模式

- 普通单模型、纯 API 和其他非多模型模式仍保留原有根级上下文窗口行为喵~
- 根配置中的模型、供应商、认证、MCP、插件、外部提示词和用户自建 `[profiles.*]` 等非目标配置保持不变喵~
- 管理器预览只删除 TOML 根级的两个窗口键，不删除嵌套 profile 中同名的用户配置喵~

### 管理器与三语说明同步

- 自定义多模型预览现在与实际写入一致，不再展示一个会覆盖全部模型的根级窗口喵~
- 中文、英文和俄语界面都明确说明：多模型模式由模型目录逐模型生效，切换模型后使用对应窗口和压缩阈值喵~
- README 的中英俄“模型与上下文”章节已补充根级全局覆盖、逐模型目录和普通单模型行为的区别喵~

## 当前 Codex 实际契约验证

本次使用当前安装的 Codex `26.917.9434.0`、CLI `0.155.0-alpha.16.4`、隔离 `CODEX_HOME` 和本机假 Responses 上游完成两次真实 app-server turn，均成功结束且实际请求模型为 `gpt-5.6-sol` 喵~

| 配置 | Codex 报告的 `modelContextWindow` |
| --- | ---: |
| 根配置保留 Terra 的全局覆盖 | `272000` |
| 根配置移除覆盖，只使用 Sol 模型目录 | `1050000` |

该正反结果直接验证了根因和修复后的配置优先级，不依赖仅检查文件文本的模拟判断喵~

## 视频背景状态

本轮同时检查了用户反馈的“Codex 更新后视频背景失效”喵~

当前实例中的视频覆盖层存在并覆盖主窗口，媒体 `readyState=4`，播放时间持续推进，连续画面哈希不同，诊断日志持续记录 `renderer.wallpaper_ready kind=video`，截图中能够看到实际视频画面喵~

因此本版不重写已经真实播放成功的 File/Blob、CDP 和 renderer 媒体链路，也不恢复已在 v1.0.24 删除的 Wallpaper Engine 原生 Scene/Web；图片、GIF/APNG、视频和旧项目静态预览行为保持不变喵~

## 升级与使用

1. 安装完整 v1.0.25 安装包，或完整替换 ZIP 中的启动器、管理器和配套程序，不要混用不同版本文件喵~
2. 在供应商的自定义多模型设置中确认每个模型自己的上下文窗口和自动压缩阈值，并选择需要的启动模型喵~
3. 保存后，在方便时退出旧 Codex，再通过新版 Alunixa X 启动，使新的 `config.toml` 和模型目录在新进程中生效喵~
4. 不需要删除旧对话、模型目录、API Key、任务记录或整个配置；本次开发没有自动修改真实用户配置、重启正在运行的 Codex 或替换当前进程喵~

## Русский

### Исправление контекстного окна для нескольких моделей

После обновления Codex до `26.917.9434.0` окно контекста в менеджере могло отличаться от фактического значения внутри Codex. Причиной были глобальные параметры `model_context_window` и `model_auto_compact_token_limit` в корневом `config.toml`: они имели приоритет над отдельными значениями моделей в `model_catalog_json`.

В v1.0.25 профиль с несколькими моделями больше не записывает эти глобальные переопределения. Окно и порог автосжатия каждой модели хранятся только в каталоге моделей. Смена модели сразу использует её собственные значения; одномодельные профили и Pure API сохраняют прежнее поведение.

На текущем Codex выполнена реальная проверка app-server: при корневом переопределении `gpt-5.6-sol` получала окно `272000`, а после его удаления — значение каталога `1050000`. Оба тестовых диалога успешно завершились через Responses API.

Предпросмотр менеджера, аудит запуска, сохранение и переключение провайдера используют один контракт. Вложенные пользовательские `[profiles.*]`, ключи, MCP, плагины и внешние инструкции не удаляются.

Видеообои на текущем Codex также проверены: видео декодируется, время воспроизведения увеличивается и кадры изменяются. Поэтому рабочая медиасистема не переписывалась, а удалённая в v1.0.24 нативная поддержка Scene/Web Wallpaper Engine не возвращается.

Установите полный пакет v1.0.25, сохраните профиль и перезапустите Codex через Alunixa X в удобное время. Удалять диалоги, каталог моделей или всю конфигурацию не требуется.

## English

### Per-model context windows on Codex 26.917

After updating Codex to `26.917.9434.0`, a context window saved in the manager could differ from the value actually reported and used inside Codex. Root `model_context_window` and `model_auto_compact_token_limit` entries were global overrides, so they took precedence over per-model metadata in `model_catalog_json`.

Version 1.0.25 stops writing those root overrides for multi-model profiles. Each model keeps its own context window and compaction threshold in the catalog, and a model switch immediately uses the matching entry. Regular single-model and Pure API profiles retain their existing root-limit behavior.

A real app-server contract check on the current Codex showed `gpt-5.6-sol` limited to `272000` while the root override was present and restored to its catalog value of `1050000` after the override was removed. Both Responses API turns completed successfully.

Manager previews, profile saves, model switching, normalization, and startup audit now enforce the same contract while preserving nested user profiles, credentials, MCP servers, plugins, and external instructions.

Video wallpaper was also checked on the current Codex build: the media is decoded, playback time advances, and frames change. The working media path is therefore not rewritten, and native Wallpaper Engine Scene/Web support removed in v1.0.24 is not restored.

Install the complete v1.0.25 package, save the profile, and relaunch Codex through Alunixa X when convenient. No conversation, model catalog, or full configuration reset is required.
