# Alunixa X v1.0.24 — 稳定背景恢复，移除 Wallpaper Engine 原生场景

## 本次按反馈作出的取舍

用户反馈背景仍不显示、打开后还弹出 Wallpaper Engine 窗口，并允许必要时回到最初的图片背景喵~

已证实旧版有两个独立问题：正式数据启动器漏接壁纸路由，真实请求返回 `Unknown bridge path`，而隔离测试单独接线掩盖了错误；原生场景通过可见 pop-out 渲染，之后仅置底并不等于隐藏喵~

本轮离屏试验虽然解决可见窗口，却在真实 Native Web 测试中产生黑画面，因此**不发布离屏试验，不继续保留不可靠的原生场景功能**，优先交付不依赖 Wallpaper Engine 的背景路径喵~

## 修复、移除与保留

### 修复真实媒体接口

- 两种正式启动器与 Electron 实播fixture统一使用renderer bridge安装入口，修复 `/wallpaper/media` 落入通用未知路由的问题喵~
- 普通图片保留原覆盖层及适配方式，大图/视频使用仅限用户所选媒体的磁盘后备File/Blob，不放开Codex CSP、不把整段视频转成Base64、不开放任意文件读取喵~
- 保留Blob/视频源/临时input回收及正常页面导航后的恢复喵~

### 移除原生 Wallpaper Engine Scene/Web

- 删除原生引擎启动模块与所有启动调用，不再创建引擎窗口、不做窗口/桌面捕获、不执行项目HTML或脚本喵~
- 删除项目目录与引擎程序选择按钮，以及原生场景、Web项目资源服务和renderer捕获分支喵~
- 旧 `codexAppWallpaperEnginePath` 仅作为兼容字段原样保存，不再用于启动或校验，用户无需手动删除喵~

### 保留已验证的图片、动图与视频

- PNG/JPEG/BMP/静态WebP继续作为图片背景；只需图片时直接上传，无需配置任何引擎喵~
- GIF/APNG和视频导入、原字节保存、预览、循环、透明度、适配、静音与暂停保留；MP4/WebM已进入严格宿主实播门禁，其他格式取决于实际编码喵~
- 旧Video项目配置仅兼容读取已有视频；新设置直接上传媒体文件喵~
- 俄语管理器、三语选择、README与guardianv2定向配置修复保留，不回退整个应用版本喵~

## 旧场景配置如何降级

旧Scene/Web设置有有效的项目内预览图片时，明确显示为**静态预览**，同时提示“旧场景只显示预览图片，不运行场景”；没有可用图片、路径越界或指向非图片时不加载并提示上传新图片/视频喵~

不修改原 `project.json`、`scene.pkg`、桌面壁纸、任务或供应商配置；静态预览不是“场景播放成功”的替代说法，项目效果和脚本不会运行喵~

## 使用与升级

1. 安装本版或完整替换本版ZIP中的启动器、管理器和配套程序，避免混用不同版本喵~
2. 在 **皮肤管理 → 动态壁纸** 上传PNG/JPEG等图片，即可使用原图片背景；需要时也可选择GIF/APNG/视频喵~
3. 保存后，在方便时退出旧Codex并通过新版Alunixa X启动；只打开新版管理器不会替换已经运行的旧启动器或Codex代码喵~
4. 无需删除任务、重设供应商或清空整个配置；本次开发没有自动重启你的Codex或关闭正在运行的桌面引擎喵~

## 验证与发布

- 增加生产入口WebSocket路由、禁用保护、错误资源拒绝、普通路由共存与两种正式入口防绕过回归喵~
- 增加旧场景静态预览、缺图、路径逃逸、非图片拒绝、原文件不变、原生启动/捕获移除及UI明确标记回归喵~
- 独立Electron验证严格CSP下的图片、大图、动画、视频跳转/循环、清理和旧项目预览，不操作用户当前Codex实例喵~
- 验证器失败改为明确非零退出，同时必须出现最终PASS标记；不会再把“退出0但内部打印黑屏错误”当作成功喵~
- 新标签由唯一GitHub Actions完成Windows x64、macOS x64/arm64全量测试、编译、打包与六资产Release，来源及SHA-256附在下方；不升级第三方依赖或覆盖旧发行喵~

## Русский

### Стабильный фон вместо ненадёжных сцен

В v1.0.22/v1.0.23 реальный лаунчер не подключал интерфейс медиа и возвращал `Unknown bridge path`, хотя отдельный тест проходил. Теперь оба лаунчера и проверка воспроизведения используют одну точку подключения моста.

**Нативная поддержка Scene/Web Wallpaper Engine удалена.** Перемещение окна за пределы мониторов дало чёрные кадры, поэтому этот эксперимент не выпускается. Программа больше не запускает движок и отдельное окно, не захватывает рабочий стол и не выполняет HTML/скрипты проектов. Выбор папки проекта и программы движка убран из интерфейса.

Обычные изображения PNG/JPEG/BMP/WebP, анимация GIF/APNG и локальные видео сохранены. Для первоначального фона достаточно импортировать картинку. Для видео остаются повтор, отключение звука, пауза, непрозрачность и масштабирование; формат зависит от кодека. Русский интерфейс и исправление guardianv2 сохранены.

Старые Scene/Web используют только доступную картинку-превью внутри проекта с явной меткой **статичного превью**. Это не воспроизведение сцены. При отсутствии картинки, выходе пути за пределы проекта или выборе не изображения загрузка отклоняется; импортируйте другой файл. Исходные проекты, задачи и настройки провайдеров не изменяются.

Установите полный пакет v1.0.24, сохраните фон и при удобном случае заново запустите Codex через новый Alunixa X. Уже запущенные пользовательские процессы автоматически не заменяются. Все шесть файлов выпуска собираются заново в GitHub Actions; ошибка реального воспроизведения теперь гарантированно возвращает ненулевой код теста.

## English

- Fix missing media routes in the real data-aware launcher; both production launchers and the playback fixture now share one renderer bridge entry point.
- **Remove native Wallpaper Engine Scene/Web support.** The off-screen experiment produced black frames and is not shipped. No engine process/window, desktop/window capture, or project-script execution remains in the wallpaper path.
- Keep the original still-image background, GIF/APNG and optional local video controls. Wallpaper Engine is not required. Large media retain restricted disk-backed File/Blob transport under the existing CSP.
- Existing Scene/Web settings fall back only to an explicitly labelled in-project preview image. Missing, escaping, or non-image previews fail with a request to select another media file; projects and unrelated settings remain unchanged.
- Remove project-folder/engine pickers, retain legacy engine-path data only for configuration compatibility, and preserve Russian localization and guardianv2 repair.
- Add production dispatch, retirement, static fallback, path-isolation and UI regression coverage. Fix the playback verifier so failures exit nonzero and require an explicit final PASS marker.
- Install the complete matching-version package and relaunch Codex through Alunixa X when convenient. No task deletion or automatic replacement of running user processes is required.
- Fresh Windows x64 and macOS x64/arm64 builds, full CI tests, six release assets and SHA-256 provenance below; no third-party dependency upgrade or historical tag changes.
