# 供应商与增强功能恢复记录

## 对照范围

以 Alunixa X v1.0.35 的可用功能对照 v1.0.38 的上游整合结果，本次保留新架构与协议修复，恢复被错误撤下的已实现功能。

| 功能 | 恢复位置 / 链路 |
| --- | --- |
| 高级自定义供应商 | 供应商列表和添加目录的直达按钮 |
| 独立模型配置 | `CustomModelsEditor`：地址、密钥、五协议、窗口、压缩、思考、默认、排序、测试 |
| 原生能力设置 | `EnhanceScreen` + Agent 健康审计 + 显式 `capabilityWrites` / 修订号保护 |
| 提示词、记忆、AI Shell | 设置保留、Instructions 文件策略和启动前 Hook 安装 |
| 共享终端 | 每次 Helper 会话自己的 broker；HTTP CLI 提交与 renderer 桥接操作共享同一实例 |
| 语言、启动、性能 | 受设置约束的原生注入、自己补丁的退出清理、启动参数与工作区保护 |
| 更新、原生菜单、Guard | 实际启动策略、单进程 inspector、Windows Guard 配置保留 |
| 项目移动、worktree、Zed | 会话菜单、原生适配和实际数据/工作树/远程项目路由 |
| 手机远控和账号连接 | 独立页面，官方运行时的登录、取消、退出、配对和设备管理 |
| 用量 | 本机 rollout/SQLite 数据统计，不用固定假数字代替 |
| 插件缓存 | 手动修复与释放内置缓存；兼容模式不执行完整模式的请求改写 |

## 回归要求

- 保留全部升级前增强 form 字段；下一步建议等已迁入子面板的字段按完整挂载页面核对，不重复放入旧面板。
- 新建供应商测试必须从真实入口开始，不能只注入一个已经存在的自定义供应商后宣称创建能力可用。
- 测试独立模型的保存、重开、重新加载、默认、排序、压缩和思考；校验无效草稿以及保存增强不删除供应商。
- 原生设置只提交明确编辑的字段，失败不前进修订号；保存其他设置不能抹掉用户原生配置。
- 共享终端覆盖 HTTP 与桥接的同一 broker、预检、结果回传、停止、过期和不可重放边界。
- 功能退役断言改为恢复后的正向功能和负向保护；不新增 skip，不放宽权限/所有权/配置保留断言。
- 继续测试 v1.0.38 的原生 Anthropic/SSE/签名/缓存和其他协议，不把功能恢复做成整体回退。

## 验证边界

使用真实 Chromium、隔离设置、临时文件和本机服务夹具；正式三平台测试与构建以 v1.0.39 的成功 GitHub Actions 为准。当前用户的 Codex、账号、密钥、会话与系统代理没有被重置、安装或重启。

原先没有实现的 Zed settings 同步仍显示为不可用；本次不恢复广告，也不擅自恢复此前由用户明确同意撤下的原生 Wallpaper Engine 场景执行。

本机最终冻结验证：Rust 74 个结果块，2243 通过 / 0 失败 / 9 项既有忽略；Node 639 项，638 通过 / 0 失败 / 1 项既有 skip；TS、Vite、三语、实际 Chromium、新建/保存/重开和实例 broker HTTP/桥接闭环、安装器 12 项、格式、分片、品牌、版本和链接均通过。前序失败日志只作为修复证据。
